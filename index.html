The Problem

The charger went offline. OCPP says "faulted." That's all anyone knows.

Charge Point Operators call the service company. The tech drives out, power-cycles the charger, and drives back. It runs for a day, then fails again. No root cause. No trend. No data.

The reason is structural: OCPP monitoring reports protocol state — what the charger software knows. It cannot report control-power events that crash the controller before it can write a log entry.

The auxiliary power supply is the control backbone of a DC fast charger. Every relay driver, contactor coil, and controller board depends on it. When it becomes unstable — under load, over time, as components age — the charger behaves unpredictably. And nobody can see it.

System architecture

Hardware inside. Insight outside.

RS-24 fits on the charger cabinet DIN rail. It is the only device in the chain that observes the auxiliary power supply at hardware level — before, during, and after any instability event.

Cabinet

RS-24 DIN-rail mounted, inline on the aux power rail. Passive observer — does not disturb the circuit it monitors.

RS-24 Board Stack

Main board + optional Sensing Expansion + COM board. Captures voltage, current, waveform, acoustic, thermal. Stores events in on-board flash.

Cloud

Encrypted MQTT over Ethernet or cellular. Telemetry and event data stored with per-device access control. Automatic backfill on reconnect.

Dashboard

Fleet health map. Per-device trend charts. Instability event log with waveform. Commissioning PDF report. Role-based access control.

NFC tap path — no cloud required

Cabinet NFC antenna → any NFC phone → instant fault snapshot. Works offline. Works in a metal cabinet via external antenna. No app, no login. First assessment before the cabinet door is open.
